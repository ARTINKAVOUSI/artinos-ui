
ARTINOS Slider + Range
Final Specification — Portable Continuous Instrument System
Design and build the ultimate ARTINOS Slider + Range family: a compact, high-end continuous-control component system for creative tools, technical interfaces, and realtime professional workflows.
This component must combine two equally important goals:
	1. ARTINOS-grade quality
Precision, elegance, tactile interaction, refined motion, optical material language, adaptability, and professional instrument feel.
	2. Portable component architecture
ReactBits-style portability: copy → paste → import → use.
It must be able to live as a reusable production-quality React component without forcing the consuming project to adopt the whole ARTINOS architecture.
This is not just a visual concept. It must be designed so it can become a real, efficient, reusable, standalone component.

1. Core Idea
The ARTINOS slider is one compact precision surface.
It should not feel like a web slider.
It should feel like:
	a miniature high-end precision instrument embedded into the interface surface
It belongs closer to:
	• professional graphics software
	• DAWs
	• shader editors
	• color tools
	• 3D inspectors
	• technical parameter panels
not to:
	• generic web forms
	• mobile sliders
	• decorative UI bars

2. Canonical Visual Identity
The slider reads as a single integrated capsule:
[ Transmission █████████████│········ 65.00 ]
The surface itself contains:
	• label
	• active material
	• inactive material
	• seam / handle
	• numeric value
	• ticks / steps
	• detents
	• visualization
	• automation / modulation state
	• interaction feedback
There is no separate tiny slider sitting inside a decorative wrapper.
Do not build this:
[ outer capsule [ ────●──── ] ]
Build this:
[ Label ███████████│······ 65.00 ]
The full capsule is the control.

3. Material Language
The left/active portion must not feel like a flat progress fill.
It should feel like:
	a polished translucent material moving inside a recessed precision-machined optical trough
The control should communicate depth through:
	• recessed host surface
	• slightly raised active insert
	• polished edges
	• restrained transmission / frost
	• subtle inner diffusion
	• seam glow / signal highlight
	• quiet material contrast between active and inactive regions
Supported ARTINOS materials:
	• Optical Frost
	• Clear Glass
	• Smoked Glass
	• Precision Metal / Frost hybrid
Color should act mainly as signal, not body material.
Signal color may indicate:
	• active seam
	• focus
	• automation
	• modulation
	• snap / detent feedback
	• important semantic states
The whole slider should still look excellent even with minimal or no accent color.

4. Geometry
The slider is intentionally compact and professional.
Density
	• Dense: 24–26 px
	• Standard: 26 px
	• Comfort: 30 px
The default feel should remain compact, not oversized.
Radius hierarchy
Radii must be proportional, not identical:
	• outer host surface radius
	• active insert radius
	• micro-detail radius
This creates the feeling that the active insert truly belongs inside the control.

5. The Seam / Handle
The handle is not a separate knob.
The material seam between active and inactive areas is the handle.
██████████████│··········
              ↑
            seam
Default seam characteristics:
	• approximately 2–3 px visible width
	• vertically inset
	• slightly shorter than the control height
	• positioned just inside the end of the active region
	• uses signal color
	• restrained at rest
	• brighter / clearer while manipulating
The visual seam may remain extremely thin, but its effective hit zone should be larger.
Recommended near-seam handle grab zone:
	• ±12–14 px
This preserves visual precision while remaining comfortable to use.

6. Interaction Model
The interaction model should be clear, elegant, and predictable.
The slider has three main interaction territories:
A. Main Body
Used for ordinary fast manipulation.
Clicking anywhere on the slider body away from the seam:
	• immediately places the value there
	• begins dragging from that new value
Useful for quick traversal.

B. Seam Zone
If interaction begins near the seam:
	• it behaves as a direct grab
	• there is no initial value jump
	• the user manipulates the current value directly
Useful for fine direct handle control.

C. Value Zone (Precision Area)
The numeric value area on the right is the dedicated precision interaction zone.
This is a key ARTINOS behavior.
[ Roughness █████████│···· 65.00 ]
                               ↑
                     precision interaction zone
Dragging from the numeric readout activates:
	• precision scrubbing
	• off-axis sensitivity control
	• temporary HUD
	• arrow / guide
	• optional local ruler
	• additional precision digits when needed
Important rule:
	The HUD and precision guides activate only from the value area, not from the whole slider bar.
This keeps the component cleaner, more understandable, and more performant.

7. Precision Behavior
The ARTINOS slider supports both fast traversal and precision adjustment, but the system should be simplified.
Main Principle
The value readout acts like a mini precision scrubber.
Dragging horizontally over the value changes the parameter.
Moving vertically away from the value reduces sensitivity.
The precision guide originates from the value readout, not the whole slider body.

Precision Levels
Keep the precision system clean.
Do not use a long ladder like:
	• 1×
	• 1/2×
	• 1/4×
	• 1/8×
	• 1/100×
Instead use only meaningful levels.
Recommended default
	• 1× — normal
	• 0.1× — fine
	• 0.01× — ultra-fine (optional)
In many cases even:
	• 1×
	• 0.1×
is enough.
Precision levels should feel intentional and easy to understand.

Vertical off-axis logic
Use broad meaningful zones:
	• near the value: 1×
	• moderate vertical offset: 0.1×
	• deeper precision offset: 0.01× (optional mode only)
The transition may be smoothed visually, but the logic should remain simple and predictable.

Modifier behavior
Use clean modifier rules:
	• Normal → 1×
	• Alt → fine
	• Shift → ultra-fine
	• Ctrl → snap / detent emphasis
Modifiers should compose sensibly, but should not create absurd micro-ratios.

8. Precision HUD
The precision HUD must remain small, quiet, local, and temporary.
It is not a tooltip.
It is not a dashboard.
It is not a large overlay.
It may include:
	• a small origin point
	• a short hairline or dashed guide
	• a short arrow toward the pointer
	• a subtle precision ratio label
	• extra precision digits
	• optional tiny local ruler
	• snap / detent feedback
Example feel:
65.00 ─ ─ ─ ➜
      0.1×
The guide should appear only during active precision manipulation and disappear elegantly on release.
The HUD belongs around the value readout, not across the full slider width.

9. Rolling Value Display
The numeric value must behave like a living precision readout, not like ordinary text being replaced.
It should feel somewhere between:
	• a mechanical counter
	• a premium digital instrument
	• a precision display module
Core behavior
Only the digits that change should animate.
Example:
65.39 → 65.40
Unchanged digits remain visually stable.
Only changing digits roll.

Direction-aware rolling
Digit motion should reflect the direction of change:
	• increasing value → digits roll upward
	• decreasing value → digits roll downward
This creates a direct relationship between gesture and numerical motion.

Carry transitions
When a value crosses a carry boundary:
59.99 → 60.00
the digits should resolve as one coordinated motion, not as unrelated character swaps.
A tiny coordinated stagger is acceptable, but the whole event should feel like a single mechanical resolution.

Motion character
The rolling number should feel:
	• quick to respond
	• smooth
	• controlled
	• softly settled
	• non-bouncy
	• non-cartoonish
	• instrument-like
It should not feel like:
	• a slot machine
	• a flashy odometer
	• a springy text effect
	• a crossfading DOM string

Direct-manipulation timing
During drag, the readout must remain tightly synchronized with the hand.
The semantic value updates immediately.
The digit motion follows almost instantly.
Use very short motion while dragging, slightly slower when settling or when values change programmatically.

Precision expansion
During fine control, the display may reveal extra decimals.
Normal:
65.00
Fine:
65.004
Ultra-fine:
65.0047
These extra digits should appear gracefully, not pop in abruptly.
When the interaction ends, the display can collapse back to the canonical formatted value.

Stable layout
The value readout should remain visually stable:
	• right aligned
	• tabular / fixed-width numeric layout
	• decimal point remains anchored
	• unit remains anchored
	• unchanged digits remain still
This is especially important because the numeric readout is also the precision interaction region.

10. Motion Language
The slider should feel more polished and alive, but always controlled.
Every motion should communicate one of these:
	• engagement
	• movement
	• precision
	• snap
	• settle
If an animation does not communicate one of those, it likely should not exist.

Hover
Very subtle only:
	• slight increase in clarity
	• small material lift / brightness
	• seam becomes a bit more visible
	• value readout slightly strengthens
No exaggerated scaling or glowing.

Pointer down
A tiny engagement cue:
	• microscopic compression
	• subtle internal depth shift
	• slight seam activation
It should feel like contact with a precision instrument, not like pressing a button.

Drag
The semantic value remains immediate.
Visual material motion may use restrained damping to communicate weight and polish, but the control must never feel laggy.

Seam grab
When directly grabbing the seam:
	• seam becomes clearer
	• glow / definition subtly increases
	• active insert feels slightly more engaged

Precision engagement
When dragging from the value area:
	• numeric readout wakes up
	• origin point appears
	• short guide / arrow grows out
	• precision ratio or extra digits may appear
This should feel coordinated and elegant.

Detent response
Detents should produce:
	• slight attraction
	• tiny settle
	• restrained snap confirmation
No rubber-banding or sticky frustration.

Release
On release:
	• guides fade out
	• extra precision digits collapse if needed
	• value settles into resting state
	• active emphasis gently relaxes

11. Mappings

Supported mappings include:
	• Linear
	• Logarithmic
	• Exponential
	• Power
	• Decibel
	• Angle / cyclic
	• Bipolar
Critical rule:
	The underlying semantic value remains exact. Only visual mapping / display geometry changes.

13. Bipolar / Neutral Values
For bipolar values, neutrality is semantic, not just geometric.
The center should read as a meaningful resting state.
The control should communicate direction and sign clearly while preserving the same ARTINOS slider identity.

14. Range / Multi-handle
Range controls should preserve the same language:
	• same material system
	• same seam logic
	• same precision philosophy
	• same motion language
	• same performance standards
For multi-handle ranges, only the active handle should receive strong feedback.

15. Steps and Detents
These must stay powerful but simple.
Stepped slider
steps={6} means true quantized values.
It must not be only visual decoration.
For small step counts, ticks may be displayed clearly.
For larger counts, visual complexity should stay restrained.
Detents
Detents are semantic magnetic points.
They should feel useful, deliberate, and predictable.
They must cooperate with:
	• direct manipulation
	• precision control
	• snapping
	• stepped modes
	• semantic neutral positions
Implementation should stay lightweight and not create unnecessary complexity or large DOM structures.

16. Adaptive Text Contrast
When text sits over the active material, it should switch to the appropriate fill-relative contrast color.
This applies to:
	• label
	• value
	• optional badges
Text must remain readable regardless of whether it is over active or inactive material.

19. Automation / Modulation / Status
The slider may show subtle semantic states such as:

	• keyframed
	• recording
	• overridden
	• modulation amount
	• bound
	• warn
	• error
These must stay subtle and integrated.
Do not transform the slider into a separate widget type just because a state is active.

20. Wheel / Keyboard / Touch
Wheel
Wheel editing is guarded.
Wheel changes a value only when the slider is focused.
	• wheel → standard increment
	• Alt + wheel → fine increment
	• Ctrl + wheel → snap

Keyboard
Keyboard behavior follows the same precision logic:
	• arrow keys → increase / decrease
	• Alt → fine
	• Shift → ultra-fine
	• Ctrl → snap
	• Home → min
	• End → max
	• Escape → cancel active drag

Touch
Use:
touch-action: pan-y;
This allows vertical scrolling in inspectors while still enabling intentional horizontal manipulation.
Touch adaptation should preserve the compact ARTINOS form rather than turning the slider into a large generic mobile control.

21. Double-click Enable / Disable
The slider may optionally function as its own enabled/off state.
Double-click behavior:
	• first double-click → disabled / off / zero state
	• second double-click → restore prior active value
A small visual indicator may be used if useful, but it should remain extremely restrained.

22. Performance
This component is intended for professional realtime environments.
It must remain efficient enough for:
	• shader editing
	• 3D inspectors
	• graphics tools
	• audio tools
	• simulation controls
	• high-frequency updates
	• dense parameter panels
Avoid:
	• permanent RAF loops
	• decorative continuous animation
	• excessive DOM for ticks or detents
	• unnecessary React rerenders for purely visual changes
	• heavy layered effects that destabilize rendering
	• noisy interaction models
Steps, detents, and visual overlays should remain deliberate and lightweight.

23. Portability Rule
The component itself is the reusable unit.
The workflow must be:
copy → paste → import → use
A consuming project should not need to rebuild ARTINOS to use it.
If helper utilities exist, they must be:
	• local
	• minimal
	• explicit
	• understandable
	• portable
The component can be sophisticated internally, but its integration contract must remain simple.

ARTINOS Slider — Handle, Moving Ruler & Enable-State Refinement
1. Exact Seam / Handle Geometry
The ARTINOS slider does not use a conventional draggable thumb.
The handle is the termination seam of the active material itself.
╭─────────────────────────────────────────────────────╮
│ LABEL ███████████████████│·············· 65.00   │
╰─────────────────────────────────────────────────────╯
                          ↑
                    seam / handle
The active surface ends at the current parameter position, and the seam is embedded directly into that boundary.
Exact visual relationship
The seam must sit slightly inside the active material, not outside it and not centered loosely over the boundary.
ACTIVE MATERIAL
███████████████████│
                 ↑ │
          seam inset slightly
Think of it as a small machined marker embedded into the polished moving insert.
Recommended geometry
For a 24–30 px high slider:
Visible seam width:      2–3 px
Visible seam height:     ~35–50% of control height
Vertical position:       centered
Horizontal position:     1–3 px inside active-material end
Corner radius:           ~1–2 px
For a 26px slider, a good starting point is approximately:
height: 8–11px
width: 2px
The seam should never extend from top to bottom.
That makes it feel like a precision reference mark rather than a dividing line.

2. Seam Construction
The seam can visually consist of two very restrained parts:
██████████████████▐│······
                  ↑
       subtle shadow + signal line
Primary marker
A narrow dark or signal-colored line.
Secondary depth
A microscopic adjacent shadow/highlight that makes the seam appear physically inset into the active material.
No obvious bevel.
No thick grab handle.
No circular knob.
No large glowing bar.
At rest, the seam should almost disappear into the material.
During manipulation it gains slightly more contrast.

3. Seam Interaction Area
The visible handle stays tiny, but its actual hit region is larger.
           invisible grab area
        ←───────────────→
██████████████│··········
              ↑
         visible seam
Recommended:
±12–14px around seam
If pointer-down begins inside this region:
	• grab current value
	• do not jump
	• begin direct manipulation from current position
If pointer-down begins elsewhere:
	• move immediately to clicked location
	• begin normal drag
This preserves both fast traversal and deliberate precision.

4. Seam Motion
The seam must remain visually locked to the semantic value, not to a delayed animation.
The actual boundary follows the parameter immediately.
However, material lighting around it may have a tiny amount of delayed response:
value / seam position
──────────── immediate
surface highlight
──────────────╮
              ╰─ tiny settle
This gives physical polish without creating input lag.
During grab
The seam can subtly:
	• sharpen
	• increase contrast
	• gain a restrained signal highlight
	• reveal a tiny surrounding halo
	• slightly strengthen the active material edge
On release, these settle back smoothly.
No bounce.

5. Ruler Slider — Different Control Model
The ruler-style sliders in the reference should not behave like ordinary progress sliders.
They should behave like a moving precision scale viewed through a fixed index.
The central indicator stays fixed.
The ruler moves underneath it.
                  FIXED INDEX
                      ↓
35    40    45    50  │  55    60
│····│····│····│····│····│····│
                      ↑
                   VALUE
The value is whatever scale marking is directly aligned with the fixed indicator.
This is the key interaction model.

6. Camera / Lens Scale Behaviour
Think of:
	• camera focus rings
	• aperture rings
	• precision measurement scales
	• mechanical verniers
	• editing scrub strips
The user's drag moves the scale, not the indicator.

or simply alter its luminance.

The fact that the slider itself is active/dormant should communicate most of the state.

24. Disabled Interaction Rules
When disabled:
	• normal body drag does not modify the value
	• seam does not manipulate
	• ruler does not scroll
	• wheel changes are ignored
	• keyboard value changes are ignored
But:
	• focus may still work
	• double-click remains available for reactivation
Optionally, a single click can focus it without turning it on.
This makes the state predictable.

27. Final Rule
The interaction can now be summarized very cleanly:
MATERIAL SLIDER
drag surface
→ value position moves
drag seam
→ direct value grab
drag value
→ precision scrub + local HUD
RULER SLIDER
drag surface
→ scale moves beneath fixed index
fixed center index
→ defines current value
drag value
→ precision scrub / finer ruler resolution
DOUBLE CLICK
→ toggle parameter active/off
double click again
→ restore preserved value
The resulting system feels much closer to precision photographic equipment, DAW instrumentation, optical measurement tools, and high-end creative hardware rather than a web slider.
And importantly, the two visual languages remain consistent:
	The standard slider moves its material beneath a movable seam.
	The ruler slider moves its engraved scale beneath a fixed seam.
	Both communicate value through the same ARTINOS precision-instrument language.
	Both can become dormant and reactivate through an integrated double-click switch interaction.
